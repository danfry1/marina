Every port, and who's berthed there.

Coding agents start dev servers and don't always stop them. marina names the session behind each one, flags what a finished session left behind, shows what's eating your CPU, and cleans up with one command.


      

    

  


  

    

      
Ten agents, no port fights.

      
marina port gives each project and worktree its own stable port, so parallel agents stop colliding on :3000.

      
An agent can ask marina about its own servers with --mine, and stop exactly those when it's done. --json on ls, kill, url, who, free, port and agents keeps scripts and agents on a stable contract.

      
Agents only use it when they're told to. Paste this into CLAUDE.md or AGENTS.md:

      
## Dev servers
- Run servers on `$(marina port)`, not a fixed port.
  One per service: `marina port <name>`.
- Your server's URL: `marina url --mine`.
- When done, stop yours: `marina kill --mine`.

      
Enter on a session jumps to it in herdr, tmux, iTerm2, WezTerm, Ghostty or Terminal.

And the small things.

    

      
Logs, inline
t tails a server's log file when it writes one. R restarts it with its output captured, so t always works after that.

      
LAN warnings
A server bound to 0.0.0.0 shows :3000!, so you know it's reachable from the network.

      
Crash notices
If a long-running server dies without you killing it, marina says so.

      
Docker too
Published container ports show up as rows, and a [[group]] rule files one with its app. X, R and t use the docker CLI.
